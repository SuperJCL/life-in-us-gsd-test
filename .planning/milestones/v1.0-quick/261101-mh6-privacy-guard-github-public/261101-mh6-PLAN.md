   入口与工具函数：
   - 启动时用 `git rev-parse --show-toplevel` 得到仓库根目录，并 `process.chdir` 过去。
   - 所有 git 调用都用 `execFileSync('git', args, { encoding: 'buffer', maxBuffer: 64 MB })`。
   - 所有路径列表都用 `-z` 输出、按 NUL 切分，避免 `core.quotepath` 把中文文件名转义，从而漏掉含“备份”的文件名。

   纯函数，供四种模式和自检共用：
   - `checkPath(path)` 实现规则 A。比较前统一成正斜杠。匹配条件：
     - basename 等于 `us-journey-tracker.html`；
     - basename 含“备份”并以 `.json` 结尾；
     - basename 匹配 `在美国的日子-*.json` 或 `在美国的日子-*.csv`；
     - 任一路径段等于 `private`；
     - 完整路径等于 `.claude/settings.local.json`；
     - basename 以 `.env` 开头。
   - `scanText(location, text, terms)`：
     - 去掉 BOM，按 CR/LF 的任意组合分行，行号从 1 开始；
     - 对每一行运行规则 B、C，以及 Task 2 加入的规则 D；
     - 同一行同一条规则最多报一次。
   - `isBinary(buffer)`：前 8000 字节里有 NUL 就判为二进制。
   - `formatFinding(finding)`：输出一行 `<位置> [<规则ID>] <中文说明>`。规则 ID 固定为 `A-forbidden-path`、`B-abs-path`、`C-email`、`D-plan-term`、`E-author-email`（D、E 在 Task 2 实现，这一步先把 ID 定好）。

   规则 B 的匹配方式（带 `u` 标志）：
   - 用户名段：首字符是字母、数字或下划线，后续是字母、数字、点、下划线或连字符，最长 64 个字符。首字符的限制让 `<名字>`、`...`、`{user}`、`$USER`、`%USERPROFILE%` 这类占位写法自然不命中。
   - Windows：盘符字母后跟冒号，再跟一个或多个正斜杠或反斜杠，然后是不区分大小写的 Users，再跟一个或多个斜杠和用户名段；盘符前面不能紧挨字母。
   - macOS / Linux：`/Users/` 或 `/home/`，后跟用户名段，再跟 `/`。前面不能紧挨字母、数字、下划线、点或冒号。排除冒号是为了不和 Windows 写法重复报，排除前面三类字符是为了不误报 URL 里的路径。
   - 用户名不区分大小写地等于 Public、Default、Default User 或 All Users 时放过。
   - 输出时把用户名替换成 `<用户名>`，并截断到用户名为止。

   规则 C 的匹配方式：
   - local part 是字母、数字和 `._%+-`；域名是若干由点分隔的标签，最后是至少 2 个字母的顶级域名。
   - 以下情况放过：域名以 `users.noreply.github.com` 结尾；整个地址等于 `noreply@anthropic.com`；域名是 example.com、example.org 或 example.net；顶级域名是常见文件扩展名（png、jpg、jpeg、gif、svg、webp、ico、js、mjs、cjs、ts、json、md、css、html、htm）。
   - npm 作用域包名前面没有 local part，因此天然不会命中。
   - 输出时 local part 只保留首字母，其余换成 `***`，例如 `j***@domain`。

   `--staged` 模式：
   - 用 `git diff --cached --name-only -z --diff-filter=ACMR` 取暂存的路径。
   - 每个路径先跑 `checkPath`。命中规则 A 的文件只报这一条，不再扫内容，避免误加入的应用文件刷出大量结果。
   - 其余文件用 `git show ":<path>"` 读暂存区里的 blob，二进制跳过，然后运行 `scanText`。
   - 没有暂存文件时，向 stderr 输出中文提示并返回 0。

   `--self-test` 模式：
   - 在一张样例表上跑上面的纯函数，用例覆盖 behavior 里列出的全部正例和反例。
   - 不依赖 git 状态，也不依赖应用文件。
   - 全部通过时，向 stdout 输出“自检通过：N 项”，返回 0。有任何不符时，逐条输出“自检失败：<用例说明>”，返回 1。

   **关键要求：检查器自身的源码必须能通过 `--staged` 和 `--all`，而且不能靠豁免自己来做到。** 所有会被规则 B、C 判为命中的正例样本，都要在运行时拼出来，例如 `['C:', 'Users', 'someone', 'x'].join('/')`，或者用 `@` 连接 local part 和域名两个片段。不要在源码里写出完整的命中字面量。允许列表里的地址和占位写法可以直接写。

   输出约定：
   - 发现的问题逐行写到 stdout，每行一条。
   - 提示和汇总写到 stderr。通过时写“隐私检查通过（模式、文件数）”；未通过时写“隐私检查未通过：共 N 处问题。请修改后再提交，不要用 --no-verify 绕过。”
   - 有问题返回 1。参数错误或 git 调用失败时，输出中文错误并返回 2。
