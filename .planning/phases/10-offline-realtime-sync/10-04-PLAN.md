<objective>
把 D-07 的条目计数接到每一个改动 state 的操作上，同时把这些操作记录成可以安全重做的形式，作为 D-04 重做（10-06）和“上传等待期间先应用远端再重做”（10-07）的基础。

- Task 1 是 tracer：`commit(keys, run)` 和操作记录 `ops` → 记录类操作（记一笔、删除和撤销、编辑弹窗、拖拽）改走 commit → 上传开始时记下 `sentOps`，成功后只移除已上传的前缀、touched 改为剩余操作的键 → 用例证明“上传途中又记的一笔”在上传成功后单独计数。
- Task 2：其余处理函数（任务进度、复盘、力量值、自定义待办、预设标签、开始日期）改走 commit，全部 run 写成幂等形式；七类条目去重计数的用例；完整默认 npm test 证明旧路径不变。

决定的落点：D-07；D-04 的“重做按 id 或键定位目标，不能沿用旧 state 里的对象引用”；沿用决定“上传成功时只有 seq 没变才清 dirty”。
本计划同时满足检查器的约束“重做本机操作不得重放服务器已经收到的操作”：两种机制都做——已知上传成功的操作离开 ops（与操作类型无关）；结果未知的上传（超时中止、答复丢失后又被服务器处理）留在 ops 里的操作，由 run 的幂等性保证重做时不会重复加入或翻转。重放本身在 10-07 实现并用用例证明。

（原 10-03 拆成 10-03 和本计划：两半改的是不同的代码区域。）
