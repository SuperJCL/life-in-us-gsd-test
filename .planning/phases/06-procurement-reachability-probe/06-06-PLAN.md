## 执行约束

- **只读与改动的界线（D-04）：** 本计划在服务器上只运行 00-status.sh（只读，经标准输入运行，不存到服务器）。01、02、03 三个脚本本计划只写、只在本机检查，**不上传、不执行**；执行在 06-08，而且要用本计划 Task 3 批准时记录的批准清单（sha256sum 格式）在上传前和执行前各核对一遍。任何文件在它所属的批次被批准之前，都不会出现在服务器上（上传本身就是改动服务器）。
- **执行方式：** 在 Git Bash 里运行；先 `set -o pipefail`；只读脚本用 `ssh -o BatchMode=yes usj 'bash -s' < tools/probe/server/00-status.sh 2>&1 | node tools/privacy/redact.mjs`。脚本经标准输入读入，所以**脚本里任何可能读标准输入的命令都要显式 `</dev/null`，内嵌的 python 用 heredoc**，否则会吞掉脚本剩下的部分。06-08 起改服务器的脚本只按批准清单逐个上传到 `/tmp/usj-probe-upload/`，再用 `bash 路径` 执行，没有这个问题。
- **脚本写法（analog：06-PATTERNS.md § `tools/probe/server/*.sh`，只借 .githooks/pre-commit 的风格）：** 首行 `#!/usr/bin/env bash`；中文文件头写用途、会改什么、失败策略、回滚办法；`set -euo pipefail`；不得出现 `set -x`；前置条件不满足时信息写 stderr 并非零退出；输出用 `KEY=VALUE` 行，不打印口令、域名、IP；需要 root 的命令用 `sudo -n`（D-04a：免密已在 Task 1 确认）。LF 行尾由 06-04 的 `.gitattributes` 保证。
- **隐私：** 脚本里不写域名和 IP；所有输出只在经过 `node tools/privacy/redact.mjs` 之后才显示、才写进 SUMMARY；SUMMARY 提交前跑 `node tools/privacy/redact.mjs --check`。
- **D-17：** 本计划不下载任何东西。PocketBase 的下载写在 02 脚本里，06-08 执行时才发生。
- **提交：** 每个自动任务一次提交，说明结尾加你的运行时要求的 Co-Authored-By 署名行；经过 pre-commit 钩子；不推送。
