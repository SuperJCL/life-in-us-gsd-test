## 执行约束

- **只读，但导出先经批准（D-17）：** 导出脚本只读打开数据库，本计划不改服务器上的任何东西；但把服务器上的数据传到本机属于下载，按 D-17 只在所有者于 Task 1 检查点批准之后运行。批准只覆盖两次导出（Task 2 一次、Task 4 一次），都用下面这条命令、输出到 `private/probe-results/`；此外任何服务器 → 本机的传输（再导出一次、scp、把服务器输出重定向到本机文件）都要另行批准。
- **脚本钉在批准的 sha256 上（D-04 的审阅原则、D-17）：** export-results.py 在服务器上以 root 运行，所以 Task 1 发出检查点之前就写好、提交，并把 `sha256sum tools/probe/server/export-results.py` 的原样输出存进 `private/probe-results/export-results.py.sha256`（被忽略，只有这一行）；所有者批准的是这个 sha256 的脚本。之后脚本有任何改动都要重新贴全文和新的 sha256 请批准，批准后才覆盖这个文件。
- **执行方式：** Git Bash，先 `set -o pipefail`；两次导出都用同一条命令链，核对和导出之间不做任何别的操作：`P=private/probe-results/export-results.py.sha256 && test "$(grep -c . $P)" -eq 1 && grep -qE '^[0-9a-f]{64} [ *]tools/probe/server/export-results\.py$' $P && sha256sum -c --strict --quiet $P && ssh -o BatchMode=yes usj 'sudo -n python3 -I -' < tools/probe/server/export-results.py > private/probe-results/<YYYYMMDD-HHMM>.json`；sha256 核对不通过时 ssh 不会运行，执行者停下报告脚本已变，回到 Task 1 的形式重新请批准；导出文件只放 `private/probe-results/`（被忽略），不暂存。
- **不等待：** Task 1 和 Task 3 是检查点，执行者在这里停下并返回；Task 1 先做完准备步骤（写脚本、静态检查、提交、钉 sha256），再等所有者批准导出；Task 3 要所有者用几个晚上组织测试，测完回复“实测完成”后才会继续 Task 4。
- **隐私：** 结果文档只写运营商、网络类型、时段、run_id 前 4 位和数字；测速站和 mtr 只写转录的汇总数字；截图、原始页面、地址栏都不进仓库。提交前 `node tools/privacy/redact.mjs --check < 文档` 退出码 0，并经 pre-commit 隐私检查。
- **写法：** 结果文档用中文，结构照 06-RESEARCH.md § 结果文档的格式；表 1、表 2、附注直接贴 `summarize.mjs --block` 的输出（连同开始和结束标记），一个字都不改；对生成段落的任何补充写在段落之外。
- **提交：** Task 1 的准备步骤提交导出脚本一次，Task 4 提交结果文档一次；Task 2 不改被跟踪的文件，不单独提交；说明结尾加你的运行时要求的 Co-Authored-By 署名行；经过 pre-commit 钩子；不推送。
