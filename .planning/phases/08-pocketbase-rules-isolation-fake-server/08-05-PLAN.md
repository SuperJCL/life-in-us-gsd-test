## 执行约束

- **前提：** 每个任务开始前，tools/pb/bin/pocketbase.exe 必须存在且 sha256 等于 instance.mjs 的 PB_EXE_SHA256（见各任务的 precondition）；不满足时停下，不尝试下载。
- **断言写法：** 用一个 `check(id, name, fn)` 注册函数登记每个编号；写类断言注册时必须带回读函数，否则注册即抛错（self-test 证明）。拒绝按四种形态断言（403、200 空、404、400）。研究表里标“实测定稿”或 [ASSUMED] 的行（ACCT04-9、-12、-13、-15、-25，TOK-1 的 exp 取法）：断言先写安全属性（被拒且回读不变）加研究给出的状态码；第一次真实运行如果只是状态码与研究不同而安全属性成立，把观察到的状态码写死进断言，并在 SUMMARY 记为“实测定稿”，再跑一遍确认。
- **安全属性不成立时：** 例如 ACCT04-13 的修饰符键改动了 owner 或 kind、任何跨账号读到了数据。不得放宽断言。在 journey_docs 迁移里按同样的 `:isset = false` 写法补上对应键的条件，同步 pb/rules.expected.json 和 migration-check.mjs 的不变量、自检，`node tools/pb/migration-check.mjs` 和本脚本都通过后再跑一遍；SUMMARY 记为偏差（规则漏洞及修法）。补不上就停下报告失败的编号和观察到的状态码。
- **改密码类断言（TOK-2、D5-1）放在最后执行**，之后需要 A 的令牌时重新登录。
- **RT-7 的正向对照不能省：** RT-7 是本计划在研究表之外补的编号（依据：users 的 listRule、viewRule 是 `id = @request.auth.id`，实时广播对 `<集合>/*` 按 listRule、对单条按 viewRule 判定）。如果 A 收不到自己账号记录的对照事件，不得删掉对照、也不得改成只断言“没有 B 的 id”；停下报告观察到的事件数和事件名（不打印 data）。
- **隐私：** 合成邮箱 `user-a-<随机十六进制>@example.com` 这类运行时拼接；口令和“故意错误的旧口令”都用 `crypto.randomBytes` 运行时生成，不写成字面量；输出不含令牌、口令、邮箱、请求体、响应体；不读 `private/`；不碰所有者的服务器。
- **资源：** 同一时间只有一个实例（REPLAY-1 在第一个实例关闭之后再起第二个）；静默窗口用 Node 的计时器，总时长控制在 1 分钟左右。
- **提交：** 每个任务一次提交，`git -c user.email=49228728+SuperJCL@users.noreply.github.com commit`，结尾加 Co-Authored-By 行；只暂存列出的路径；不用 `--no-verify`；不推送。
