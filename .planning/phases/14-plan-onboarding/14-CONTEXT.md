**Gathered:** 2026-11-12
**Status:** Ready for planning（界面有新元素：挑选列表和新按钮，规划前先做 UI 设计契约 `/gsd-ui-phase 14`）

<domain>
## Phase Boundary

云端版的新账号第一次登录时，服务器上建出的计划是空计划，目标页显示空计划卡片，不再自动放进整份示例计划。用户可以从示例计划里只挑需要的目标组和力量项。入口有两处：空计划卡片，以及编辑计划页里随时可用的「从示例添加」。

对应需求：PLAN-06、PLAN-07。

本阶段不改这些：
- 已有计划文档的账号，包括线上的测试账号。所有者自己的计划在 Phase 16 迁移时导入。
- 不配服务器的本地版：仍然显示示例计划（SEC-04、12 D-13）。
- 5 个固定类别：「可编辑类别」在 Out of Scope 里。
- 健身的界面：留给 Phase 15。

本阶段推翻了 Phase 7 D-01「示例计划是新账号的初始计划」，只针对云端新账号。

</domain>

<decisions>
## Implementation Decisions

### 新账号的空计划里留什么（所有者讨论决定）
- **D-01:** 第一次登录时，如果服务器上没有计划文档、本机也没有这个账号的缓存，就建一份空计划：
  - 0 个目标组、0 个力量项；
  - 每个类别的基础快捷词（`presets`）全部清空；
  - 每周健身目标保留示例的 2～4 天（`fitGoal: [2,4]`）；
  - 健身说明（`fitNote`）保留示例那句。

  另外三种情况沿用现有对账规则（09 的 reconcile 表），不变：已经有计划文档的账号；本机有缓存时从缓存建；创建时撞上唯一索引，改为重读服务器。— **Reversibility:** reversible — 只影响以后新建的计划文档，已建好的文档不受影响；改回来只是换回建档用的默认值。
- **D-02:** 基础快捷词清空，是所有者在三个选项里选的「全部清空」，没选「保留通用词」，也没选「跟着挑选带上对应类别的词」。
  - 从示例里挑目标组时，**不带**任何快捷词。
  - 「记一笔」里的添加和隐藏照旧记在 state 里，两层预设不变。用户可以在记一笔里自己加词，也可以在编辑计划页加基础词。
- **D-03:** 健身部分在本阶段只保留数据，界面一律不动：
  - 每周健身目标保留 2～4 天。现有代码在本周页总是显示「目标 a～b 天」，清空会显示成「0～0 天」，所以保留。
  - 所有者说健身说明「其实无所谓」，希望改成一个「说明」按钮：点一下展开或收起，第一次打开时默认展开。这个按钮放到 **Phase 15** 和健身页一起做，因为整张健身卡片会在那时搬走。

### 「从示例里挑」的入口（所有者讨论决定）
- **D-04:** 入口有两处：
  1. **目标页的空计划卡片**：现有的两个按钮「编辑计划」「载入示例计划」改成「自己建一份」（进编辑计划页）和「从示例里挑」。
  2. **编辑计划页**：随时都有「从示例添加」，计划不空也能用。

  原来只在计划为空时出现的「载入示例计划」（12 D-16、`loadSampleDraft`）由这两处取代。

### 怎么挑（所有者讨论决定）
- **D-05:** 挑选列表分两块：
  - 目标组：按**整组**挑，显示组名、类别和任务数。不能展开逐条挑任务，组里不要的任务进编辑计划页删。
  - 力量项：**逐个**挑，显示名称和目标值。
- **D-06:** 列表打开时**全不勾**。一项都没勾时，确认按钮不可用。

### 挑完之后（所有者讨论决定）
- **D-07:** 两个入口挑完后的处理不一样：
  - **从空计划卡片挑**：确认后**直接保存**到服务器，不经过编辑页草稿。保存后留在目标页，马上显示勾选的项，并提示加入了几个目标组、几个力量项。保存规则沿用编辑计划页：
    - 断网或登录过期时不能挑：入口变灰并说明原因（12 D-11、D-12）；
    - 另一台设备同时改了计划时，按现有的计划冲突处理走（12 D-07，Phase 9 D-10 的留底）；
    - 规模上限照常检查（12 D-17）。
  - **在编辑计划页里「从示例添加」**：编辑页本身就是草稿，所以勾选的项**加到草稿末尾**，和其他修改一起点「保存计划」生效，也可以放弃。这里不会单独保存，免得把用户别的未保存修改一起存掉。这是 Claude 对「挑完直接保存」在编辑页里的理解，已在总结里告诉所有者。
- **D-08:** 加入的每一项都换成全新的 `g-`、`t-`、`l-` id，做法沿用 `loadSampleDraft`。不复用 `P1`、`bench` 这类示例 id，否则会撞上同 id 的归档项、接上旧进度（12 A16）。

### 需求和路线图的措辞
- **D-09:** 路线图 Phase 14 成功标准 3 和 REQUIREMENTS 的 PLAN-07，原先写的是「确认后进入编辑计划页草稿、点保存才生效」。现在按 D-07 改成两种入口各自的行为，随本文件一起提交。

### Claude's Discretion
- 按钮文字、提示文字和挑选列表的标题，沿用现有文案风格。新文案进 Phase 16 的总体验收清单，由所有者过目。
- 计划里已经有的示例组怎么标出来：例如按组名标「计划里已有同名组」，仍然可以再加一份。不为此改变计划文档的形状（不加「来自示例」的标记字段）。
- 挑选列表的形式：桌面用对话框，手机用现有编辑弹窗那种底部面板。由 UI 设计契约定。
- 本周页、目标页在空计划下的说明文字要不要随新按钮调整。
- 空计划卡片上「从示例里挑」在断网或登录过期时，是变灰加说明，还是点了再提示。

</decisions>
