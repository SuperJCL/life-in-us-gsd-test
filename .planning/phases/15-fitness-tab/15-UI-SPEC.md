# Phase 15 — UI Design Contract（健身页）

> 本阶段在现有单文件应用上新增第五个标签「健身」（`#tab-fit`），并改动：标签栏、本周 / 日历 / 时间线里的「健身」行、目标页（力量目标卡片搬走）、编辑计划页（新增「有氧项」区，力量项上限 20）、示例挑选对话框 `dialog#sample`（新增「有氧项」一栏）。不改 5 个固定类别、「记一笔」的健身文字记录、目标组和任务。
> 全部文案为简体中文，代码、选择器、标识符保持英文。示例名称（卧推、深蹲、硬拉、引体、跑步、骑行、快走）是 `DEFAULT_PLAN` 里的通用占位，可以直接显示；文案里不出现任何真实计划文字、人名、服务器地址、域名。
> 上游来源：15-CONTEXT.md（D-01 到 D-15 已锁定，本文件不重新讨论；Claude's Discretion 各项在本文件定稿，见文末 Assumptions）；14-UI-SPEC.md（令牌、间距 / 字号子集、`dialog#sample`、选中态与禁用态、44px 触控、CSP、文案语气，原样沿用）；12-UI-SPEC.md（编辑计划页的折叠卡、校验、归档、`confirmBox`）；14-UI-REVIEW.md 与 12-UI-REVIEW.md（要避开的问题：选中态用类别色当底色、禁用按钮看起来可用、点击区域小于 36 / 44px、作用域里出现 13 / 15px 和奇数内边距、`:has()` 是唯一通道、静默失败）；现有 `us-journey-tracker.html` 的样式与渲染函数。
> 范围提醒：记录、趋势图、历史在云端版和本地版都可用（数据在 `state.workouts`）；「去编辑计划添加动作」入口只在云端版（`CLOUD&&me`）渲染，本地版用示例计划里的动作，不能编辑计划（SEC-04、12 D-13）。

## Spacing Scale

只用 4 的倍数，与 12、14 一致。

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 标签与输入框之间、行内小标记间隙、图例与图之间 |
| sm | 8px | 同一行内控件间距、组行与组行之间、芯片之间、卡片之间 |
| 12 | 12px | 动作块内边距、力量目标卡内边距、控件行与行之间 |
| md | 16px | 面板内边距、动作块之间、图表卡之间、面板标题与内容之间 |
| lg | 24px | 面板与面板之间（`#tab-fit .panel + .panel`）、`#tab-fit` 内分区之间 |
| xl | 32px | 页面底部留白（历史之后） |
| 2xl | 48px | 不使用 |
| 3xl | 64px | 不使用 |

Exceptions:
- 触控目标：≤560px 时，`#tab-fit` 里所有按钮、输入框、芯片最小高度 44px；桌面最小 36px。标签栏的 5 个标签按钮在 ≤560px 同样最小 44px。
- 图表几何（不属于间距；下面列的尺寸都落在 4 的倍数上，选中点半径 6 和目标线虚线 `6 4` 是形状参数、不是间距，不在这条声明里）：图高 160px；绘图区边距 左 40、右 12、上 12、下 24（左边留给纵轴数字，下边留给日期）；数据点半径 4；横向参考线 3 条（0、一半、最大）。
- 作用域覆盖：全局 `.ghost`（5px 10px、13px）、`.primary`（7px 14px）、`.seg button`（4px 12px、13px）、`.panel`（18px）在 `#tab-fit`、`dialog#confirm.pe` 里被覆盖到 4 的倍数和 14px，**不改全局规则**（见 CSS 骨架）。
- 12px 是本页沿用 12-UI-SPEC、14-UI-SPEC 的间距单位（4 的倍数），和 4、8、16、24、32 同属本页的间距集。
- 标签栏：现有 `nav.tabs button{padding:10px 14px}` 的奇数内边距属于现有组件，本阶段只在 ≤560px 加一条 `padding:8px 12px;min-height:44px`（为了 5 个标签放得下，见 S1），不改桌面规则。
- 本阶段所有新增间距都落在 4 的倍数上，没有"继承的奇数值"例外。

## Typography

`#tab-fit` 和新增的编辑页 / 对话框区块只用 **4 个字号（12、14、16、24）、2 个字重（400、600）**，与 12-UI-SPEC 的子集一致。

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label（图表坐标数字、图例、图下说明和读数、列标题、计数、提示行、错误文字、历史里的组明细、力量目标卡的说明行） | 12px | 400（图例和 `上次` 前缀不加粗） | 1.55 |
| Body（按钮、芯片、行内摘要、动作名外的正文、历史行摘要、对话框正文） | 14px | 400；`.primary`、芯片选中后的文字不加粗；动作名、卡片名称 600 | 1.55 |
| Input / Heading（输入框文字；面板标题 `h3`、动作块名称 `legend`、图表标题） | 16px | 输入框 400；标题 600（衬线 `var(--serif)`） | 输入框 1.55；标题 1.2 |
| Display（本周训练天数、力量目标卡的当前值） | 24px | 600（衬线） | 1.2 |

说明：
- 输入框文字一律 16px（桌面和手机相同），防止 iOS 聚焦放大，沿用 09 和 12 的做法。
- SVG 文字（纵轴数字、日期、目标线标注）统一 12px（CSS 类 `.fc-tx`）。因为 `viewBox` 宽度等于容器像素宽度（1 个单位 = 1px），文字不会随缩放变大变小。
- 作用域里不出现 11、13、15、17、18、19、28px 和 700、800 字重。现有 `.lift .lv`（28px 800）、`.lift .upd`（13px）、`.lift .ln` 不再使用，健身页用新的 `fw-` 类。
- 现有标签栏文字 15px 属于现有组件，不在本契约的字号声明里：第五个标签「健身」沿用同一个 15px，是为了和另外四个标签一致，本阶段不改标签栏字号（验收时这一处 15px 不算违反 12/14/16/24 的声明）。
- 所有动作名、有氧项名、说明文字、计划备注用 `esc()` 或 `textContent` 写入；id 进 `data-*` 前过 id 正则。

## Color

沿用现有调色板，60/30/10：

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--paper)` | 页面背景、输入框背景 |
| Secondary (30%) | `var(--surface)` | 所有面板、图表卡、动作块、对话框 |
| Accent (10%) | `var(--c-lang)` | 见下面 reserved 清单（本阶段不新增 accent 用途） |
| Destructive | `var(--red)` | 仅用于：`删除这次训练`、`移除这个动作`、`移除这个有氧项`、校验错误文字、确认框里的 `.danger` 按钮 |

Accent reserved for：
1. 键盘焦点环（全局 `:focus-visible`，不变）。
2. 状态行 `已同步` 小圆点（现有，不变）。
3. 目标页 `.group.k-lang` 等现有类别色的现有用途（不变）。

健身页自己**不使用 accent**。

类别色（`--c`/`--s`，来自 `.k-fit`，即现有「健身」类别色）在本阶段**只**用于：动作块和有氧行的 4px 左边框；折线、数据点、柱形、力量目标进度条填充、「本周训练」里已训练日的实心圆点；选中的指标 / 时间范围芯片的底（`--s`，浅色）和边框（`--c`）。文字一律 `--ink` 或 `--muted`，**不把类别色当文字底**（12-UI-REVIEW Top 1），**不把 `--c` 当文字色**（`--c-fit` 对 `--surface` 约 4.6:1，用作图形够 3:1，但不用于文字）。

- **芯片选中态**（指标、时间范围，14-UI-REVIEW Top 3 的写法）：`aria-pressed="true"` 时底 `--s`、文字 `--ink`、边框 `--c` 加 `box-shadow:inset 0 0 0 1px var(--c)`（边框变粗一档，是形状线索，不只靠颜色）。选中态靠普通属性选择器 `[aria-pressed="true"]`，不依赖 `:has()`。
- **禁用态**（12-UI-REVIEW Top 2）：`opacity:.4;cursor:not-allowed`，悬停不变色；真 `disabled` 和 `aria-disabled="true"` 两种写法都覆盖（见 CSS 骨架）。
- **一个深色块（整屏的主视觉焦点）**：整页只有记录区里的 `保存训练`（`.primary`，`--ink` 底）是深色实心块；芯片、历史按钮、翻页按钮全是浅色描边，不和它争焦点。
- **目标虚线**：`--muted` 描边加 `stroke-dasharray="6 4"`，线宽 2，旁边有 `目标 40 kg` 文字标注（不只靠虚线样式）。
- **手填历史点**：空心圆（`--surface` 填充，`--c` 描边），训练数据点是实心圆；图下有图例文字 `空心点是以前手填的记录，没有次数。`（形状加文字，不只靠颜色）。
- 警告色 `--c-job` 只用于圆点（记录区底部提示行的圆点），不作文字色，不作整块底色。
- 趋势图在浅色和深色主题下：折线 / 柱 `--c-fit`（浅 `#C2522D`、深 `#EE8B66`）对 `--surface` 都高于 3:1；参考线 `--line`；坐标文字 `--muted`；目标线 `--muted`；选中读数的竖线 `--ink`。

- **位置**：加在 `时间线` 之后，是最后一个标签（Assumptions A1：不改变现有四个标签的位置，旧用例按位置取标签不受影响）。
- **ARIA 和键盘**：沿用现有写法（`role="tab"` + `aria-selected`，所有标签都在 Tab 顺序里，Enter / Space 切换；现有标签栏没有方向键漫游，本阶段**不新增**，保持一致）。`showTab` 的列表加 `"fit"`；`GATE_ALLOW` 里 `nav.tabs [data-tab]` 已覆盖新标签，对账中也能切过去。
- **375px 放得下**：5 个标签文字宽 `2 个汉字 × 4 + 3 个汉字（时间线）`，按钮 15px 文字：4 × 30 + 45 = 165px，≤560px 内边距 `8px 12px`（左右共 24 × 5 = 120px）加间隙 4 × 4 = 16px，合计约 301px，小于 375px 视口去掉 `.wrap` 两侧 20px 后的 335px；留约 34px 余量给选中态 600 字重。≥561px 沿用 `10px 14px`（约 321px，同样放得下）。≤560px 加 `min-height:44px`。极窄屏（320px）允许 `flex-wrap` 折成两行，不横向滚动。
- **进入健身页**：滚动到页面顶部，不自动聚焦输入框；焦点留在刚点的标签上。`#tab-fit` 里有一个 `<h2 id="fit-h2" class="sr-only">健身</h2>`，读屏用户靠它定位。从本周 / 日历 / 时间线的「健身」行进入时焦点移到 `#fl-title`（见 S9）。
- 编辑计划页打开时点 `健身` 标签：经现有的离开确认（`peLeave()`），行为同其他标签。
- **目标页变化**见 S10。

### S3 (a) 今天的训练：记录区 `#fl`

**面板头**：左 `h3#fl-title`（日期是今天时 `今天的训练`，否则 `{M月D日}的训练`）；右 `<label class="fl-date">日期 <input type="date" id="fl-date" max="{今天}" value="{当前日期}"></label>`。`max` 是今天（不记未来的训练）。窄屏标题和日期换成两行，日期输入框 44px 高。

**状态行** `<p id="fl-state" role="status" class="fl-state">`（12px `--muted`，没有内容时 `:empty{display:none}`，元素始终在 DOM 里）：
- 这一天已经保存过训练：`这一天已经记过训练，改动保存后会更新。`
- 刚从本机留底恢复了没保存的内容：`已恢复上次没保存的内容。`
- 其余为空。

**一天一次，打开已有的日子就是修改（D-06）**：选到已有训练的日期，表单载入那一天已保存的内容（力量动作、各组、有氧），再加动作保存就是并进当天；没有训练的日期，表单是空的。

**草稿规则（Claude's Discretion 定稿）**：
- 表单是一份**草稿**，点 `保存训练` 才写入 `state.workouts`；`renderAll()` 重绘时**记录区不重画**（草稿有未保存内容、或记录区里有焦点时跳过，同 12 对 `#tab-plan` 的做法），防止别的设备的同步冲掉正在填的内容。记录区只在这些时候重画：打开健身页、换日期、保存 / 删除 / 放弃之后、草稿没有未保存内容时当天训练被别的设备改了。
- **本机留底**：草稿每次变化后 500ms 写入 `localStorage` 键 `usj:v2:<用户 id>:wodraft`（内容 `{date, draft}`），保存、删除、放弃、退出登录、换账号时删掉（和 `["state","plan","snapshot","importundo"]` 一起清）。重新打开健身页或刷新后，如果留底存在，载入那个日期并显示 `已恢复上次没保存的内容。`。原因：在健身房一组一组记，手机切应用后页面被系统回收，不能丢已填的组。
- 草稿有未保存内容时，**换日期**（日期框、从本周 / 日历 / 时间线 / 历史跳进来）先弹确认：标题 `换一天记录？`，正文 `这次训练填的内容还没有保存，换日期会丢掉。`，左（安全，默认焦点）`先不换`，右（`.danger`）`丢掉并换日期`。拒绝时日期框恢复原值。离开健身页（切标签）**不弹确认**：草稿留在内存和本机留底里，切回来还在。
- 页面刷新 / 关闭有未保存内容时设 `beforeunload`（同 12 S8），文字不可定制。

**力量分区** `<fieldset class="fl-sec"><legend>力量</legend>`（12px 600 `--muted`）：

1. 已添加的动作块（`.fl-ex`，按添加顺序，不按计划顺序），见 S4。
2. 添加动作：小标题 `<p class="fl-cap">点一下动作名，加进这次训练</p>`（12px muted）+ 芯片行 `.fl-pick`：计划里**未归档且这次训练还没加**的力量项，每个一个 `<button type="button" class="fl-chip" data-fl-add="lift:{id}">＋ {名称}</button>`（`.ghost` 外观，14px，圆角 999px，`aria-label="添加动作：{名称}"`，最小高度桌面 36px / 手机 44px），顺序同编辑计划。点一下：动作块追加到末尾，带一行空组，焦点移到新块第一个重量输入框，写 `#fl-live`：`已添加动作：{名称}`。
3. 芯片行末尾一个 `.ghost` 链接按钮 `去编辑计划添加动作`（`id="flGoPlan"`，仅云端版渲染；点击调用 `goPlan()`，被门控时由 `applyGate` 变真 `disabled`）。草稿不丢（见上）。**不在健身页当场新建动作**（D-03）。
4. 空和全满的情况：
   - 计划里没有未归档的力量项：芯片行位置显示一行 `.empty`：`计划里还没有力量项。`，后面仍有 `去编辑计划添加动作`。

- 离线时记录**不受限**：D-03 的理由是训练记录断网也要能记，所以保存按钮、加动作、加组、删除都照常可用；只有全局门控（对账中、连不上只读，`body[data-gate]`）会通过 `applyGate` 把记录区的写入控件设成真 `disabled`，原因在顶部横幅。门控期间图表、范围、翻页、说明、历史展开仍可用（它们是只读，要加进 `GATE_ALLOW`，见实现提示）。

- **删除这次训练**：直接删除，不弹确认，弹撤销 toast `已删除 {M月D日} 的训练` + `撤销删除`（`ms=6000`）；`撤销删除` 用同一个键把整次训练写回。删除后记录区变成该日期的空表单，焦点移到 `#fl-date`。
- **放弃未保存的内容**：弹确认，标题 `放弃没保存的内容？`，正文 `这次训练填的内容还没有保存，放弃后会恢复成上次保存的样子。`，左（安全，默认焦点）`继续填写`，右（`.danger`）`放弃内容`。确认后记录区恢复成已保存版本（没保存过则为空），焦点移到 `#fl-date`。
- 窄屏（≤560px）：`#fl-hint` 占满一整行（`flex:1 1 100%`），按钮在下面各占一行全宽（`flex:1 1 100%`），顺序自上而下 `保存训练`、`放弃未保存的内容`、`删除这次训练`，最小高度 44px，底部内边距 `calc(16px + env(safe-area-inset-bottom,0px))`。

## 无障碍与动效

- **结构**：每个面板是 `<section aria-labelledby>`，面板标题 `h3`，页面隐藏标题 `h2.sr-only`；动作块和有氧行是 `<fieldset>/<legend>`，组行是 `<ol>/<li>`，每个输入框都有 `.sr-only` 的 `<label>`（`卧推第 2 组重量（kg）`）；本周圆点是 `role="img"` 的文字摘要；进度条是 `role="progressbar"` 加 `aria-valuenow`；历史是原生 `<details>/<summary>`；趋势图 `<svg role="img" aria-label>` 加图下的 `<details>` 数据表。
- **键盘**：Tab 顺序按视觉顺序：标签栏 → 记录区（日期 → 各动作块：组行的重量 → 次数 → 删除，再 `＋ 添加一组` → `复制上一组` → `照上次填` → `移除这个动作` → 芯片行 → `去编辑计划添加动作` → 有氧同理 → `放弃未保存的内容` → `删除这次训练` → `保存训练`）→ `说明` → 指标芯片 → 范围芯片 → `上一组` / `下一组` → 各图的 `查看数据`（展开后表格可聚焦滚动）→ 有氧图的 `查看数据` → 历史各行 `summary` → 展开后的按钮 → `显示更早的记录`。Enter / Space 触发按钮和 `summary`；数字输入框里按 Enter 不提交、不新增行（记录区不是 `<form>`）。被 `aria-disabled` 挡住的按钮保持在 Tab 顺序里，原因通过 `aria-describedby="fl-hint"` 读出；真 `disabled`（`复制上一组`、翻页边缘）移出 Tab 顺序。Esc 关闭确认框（等同安全按钮）。
- **焦点**：加动作 → 新块第一个重量框；加一组 / 复制 → 新行的重量框；删一组 → 下一行重量框（没有就上一行，再没有就 `＋ 添加一组`）；移除动作 → 下一个动作块的第一个输入框（没有就芯片行第一个）；保存 → 留在 `#fl-save`；删除整次训练 / 放弃内容 / 确认换日期 → `#fl-date`；从其他视图或历史进入 → `#fl-title`；翻页到边缘 → 另一个翻页按钮；校验失败 → 第一个出错输入框。全部沿用全局 `:focus-visible` 焦点环（2px `--c-lang`）。
- **读屏**：常驻 `<div id="fl-live" class="sr-only" aria-live="polite">`（记录区操作：`已添加动作：卧推`、`已删除卧推第 2 组`、`训练已保存`、`已撤销：…`、`已显示更早的 20 次训练`）和 `<div id="fc-live" class="sr-only" aria-live="polite">`（翻页：`第 2 / 3 组：卧推、深蹲、硬拉、引体`；切换指标和范围：`已切换：总训练量，最近 3 个月`）；`#fl-state`、`#fl-hint` 是 `role="status"`；图表读数行不是 live 区域；toast 保持现有 `aria-live="polite"`。
- **图表的文字替代**：每张图 `role="img"` 的 `aria-label` 写完整摘要（动作、指标、范围、训练次数、最新值、最高值）；逐点数据靠 `查看数据` 表格；目标线、手填点、徒手改次数这些区分都有文字（目标标注、图例、小标），不只靠样式。
- **标签**：每个字段有可见或 `.sr-only` 的 label；错误通过 `aria-describedby` 关联，字段 `aria-invalid="true"`；组行、动作块的删除按钮 `aria-label` 带上动作名和组号。
- **触控**：≤560px 所有新增控件（芯片、按钮、输入框、`summary`、日期框、标签栏按钮）最小高度 44px；桌面最小 36px。
- **动效**：本阶段没有任何动画。图表直接画出，翻页、切换指标和范围、展开收起都是瞬时的；滚动用 `behavior:"auto"`；现有 `@media (prefers-reduced-motion:reduce){*{transition:none !important}}` 已覆盖进度条的 `transition`（`.fw-bar i` 不加过渡）。
- **窄屏**：单列；记录区日期换行；组行用 5 列网格；保存栏按钮竖排全宽；力量目标卡两列；折线图三张上下排；断点沿用现有 900 / 820 / 720 / 560，不新增断点（每页张数的切换也用 560）。
- **深色主题**：只用现有 token，无单独处理。

| # | 选择 | 理由 |
|---|------|------|
| A1 | 「健身」标签放在最后（`时间线` 之后），≤560px 标签内边距收窄到 `8px 12px` 并 44px 高 | 15 说"第五个标签"；不改变现有四个标签的位置，旧用例按位置取标签不受影响；375px 算下来放得下（约 301px / 335px） |
| A2 | 记录区用「草稿 + 保存训练」，而不是每填一组就自动保存；草稿 500ms 防抖写本机留底，刷新或页面被回收后恢复 | 路线图成功标准 2 写"保存后整次训练可以修改和删除"；在健身房一组一组记，页面常被系统回收，留底防丢；换日期、放弃要确认（`换一天记录？`、`放弃没保存的内容？`），切标签不确认 |
