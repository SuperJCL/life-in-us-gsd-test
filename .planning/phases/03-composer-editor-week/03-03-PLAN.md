**As a** 开发者, **I want to** 拥有可复用的记一笔、编辑弹窗和 toast 测试 helper，以及统一的已知 bug 标记约定, **so that** 用它们完整验证本周视图的渲染和交互。

（三个槽位逐字取自 ROADMAP Phase 3 的 Goal，只做了切分。）

- 视图用例默认账户模式加 `full-state.json`，开局后立刻 `app.expectAccountMode()`（D-10）。
- 只编辑合成记录（id 以 `synth-full-` 开头）和合成的自定义计划 `c-synth-2`。时间线和日历里同时有内置计划的条目：只按 `[data-edit="<id>"]`、`[data-edittask="<合成 id>"]` 定位到具体一条，不对整个 `#timeline`、`#dayPanel` 或 `#grid` 用文字类断言（D-14）。
- 失败输出脱敏要覆盖 Playwright 的调用日志（D-14，与 03-01 的执行约束同一条规则）：动作和单元素断言失败时，调用日志会打印命中元素的预览（全部属性加只含文字的子节点文字），被遮挡时还会打印遮挡元素的预览，单元素断言还会打印 Received，定位器命中多个元素时 strict mode 报错会列出每个元素。所以：
  - 内置计划的条目（属性 `aria-label` 是“编辑完成记录：”加原文）不做 Playwright 动作和单元素断言，只在需要时用 `toHaveCount` 计数；
  - 动作只落在合成条目（synth- 记录、`c-synth-2`）、日历格（`[data-date]`，属性只有日期和计数）、标签页按钮、周导航按钮和弹窗自己的控件上；弹窗只为合成条目打开，所以弹窗遮挡背景时日志里的预览也只有合成文字；
  - 每个定位器都用合成 id 精确到一条，避免 strict mode 报错列出别的条目；
  - test-results/ 和 playwright-report/ 里的截图、trace 和 error-context.md 按 PRIVACY.md 只留在本机，不把其中内容抄进任何被跟踪的文件、提交信息或 SUMMARY。
- 编辑弹窗打开时背景不可交互：操作弹窗以外的元素之前先确认弹窗已关闭。类别按钮会重绘整个表单，每一步都重新定位，不持有元素句柄。
- 时钟：默认 setFixedTime；只有证明“没有保存”的两条用例（丢弃修改、空文字）用 `test.use({ clockMode: 'manual' })` 加 `page.clock.install({ time: FROZEN_NOW })`、`pauseAt`、`runFor`，同一个用例里不混用（D-05、D-15）。不用固定睡眠。
- 如果某条用例暴露出应用行为与 FEATURES.md 第 121-130 行（ED-1 到 ED-10）的描述不一致：先确认不是测试写错；确认是应用行为时停下来报告，不改期望去迁就应用，也不自行标成已知 bug。
- 每个任务结束时 `npm test` 全绿且没有 flaky。
