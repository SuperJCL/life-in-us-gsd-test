<objective>
实现导入前的自动快照和“撤销导入”（IO-08 的后半部分，D-04、D-05）。

- Task 1：撤销槽和撤销本身。导入在改动之前把计划和记录存进独立的本机槽，存不下就拒绝导入；导入后工具栏和 toast 都有“撤销导入”；撤销先比较导入后的指纹，变了先确认（D-05），再经 commit 整份恢复并上传，另一台设备跟着恢复。
- Task 2：撤销副本的生命周期。刷新后仍在、下一次导入时被取代；退出登录和换账号时清掉，退出确认框提到它；同一浏览器的另一个标签页跟着显示和隐藏按钮；导入时挂起的远端版本会被撤销恢复回来。

决定的落点：D-04（含所有者 2026-11-10 的说明：撤销成功就用掉这份数据、入口消失；还没撤销时保留到下一次导入或退出登录）、D-05、D-09（摘要、导入前留的数据和撤销只在云端版，IO-08 在旧路径上豁免）；CONTEXT Claude's Discretion 的“快照存储”（与冲突留底两个独立槽，存不下明确告诉用户并拒绝导入）。
</objective>

## Edge 探针与假设

- IO-08（unresolved）：“导入之后有新修改”按计划和记录的指纹判断，别的设备同步来的修改也算；只有页面上的视图状态（选中的周、日历月份）变化不算。
- IO-08（unresolved）：撤销之后不能“重做导入”；要重来就再导入一次原文件。
- IO-08（unresolved）：撤销副本在“下一次导入”时被取代——新的副本是那次导入之前的数据，所以撤销只能回退最近一次导入。

- IO-08（D-09，所有者豁免）：旧路径没有导入前留的数据和撤销，验证 IO-08 时只看云端版。
