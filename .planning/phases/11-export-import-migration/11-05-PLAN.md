<objective>
同一浏览器两个标签页：一个标签页导入带新计划的备份之后，另一个标签页先采纳本机计划缓存里的新计划（`adoptPlanTab`），再采纳 state，不丢新计划任务的进度。

现在计划缓存变化只触发一次同步，另一个标签页会在旧计划下采纳导入的 state、把新计划任务的进度当孤儿丢掉并可能写回。本计划改 storage 事件的计划分支，加一条 cloud 用例。

拆分说明：本计划原来是 11-04 的 Task 3。11-04 原 estimate 110000，超出 100000 的预算（检查器第三轮警告）；这一部分和 11-04 的大小上限、合成留底没有共用的函数，只共用 tests/cloud/import-sync.spec.ts，所以单独成计划，紧接在 11-04 之后执行。只有一个任务，因为改动只有一个函数加一条用例；它改了同步核心，verify 跑完整的 cloud 套件。

决定的落点：沿用决定“同步规则（导入后上传，其他设备按 Phase 10 的规则收到更新）”；Phase 10 的“先 plan 后 state”和 10-09 的两个标签页收敛条件。
</objective>
