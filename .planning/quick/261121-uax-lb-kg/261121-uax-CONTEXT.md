# Quick Task 261121-uax: 健身页的重量支持磅（lb）和公斤（kg） - Context

**Gathered:** 2026-11-21
**Status:** Ready for planning

<domain>
## Task Boundary

健身页的重量支持磅（lb）和公斤（kg）：记录时可以选单位，显示时附带换算，用户可以自己选想要的显示单位。

范围只在健身页（第五个标签 `#tab-fit`）和账号数据里新加的单位设置。本周、日历、目标、时间线四个视图的界面和操作方式不变；计划编辑器不变。

</domain>

<decisions>
## Implementation Decisions

### 显示方式（所有者选：所选单位大字，换算小字）
- 健身页上出现重量的地方，先用所选单位显示数值，后面跟一个灰色小字的另一种单位换算。例如所选单位是 kg 时显示「60 kg ≈ 132 lb」，所选单位是 lb 时显示「132 lb ≈ 60 kg」。
- 覆盖范围：训练记录表（输入框旁的单位标注）、训练历史、力量目标卡片（当前值和目标值）、趋势图（坐标、目标线标签、数值标签）。如果某处放不下小字换算（例如图表坐标轴），只显示所选单位也可以，由 Claude 决定，但数值必须是所选单位。

### 记录单位（所有者选：一个开关管记录和显示）
- 健身页上放一个 `kg | lb` 切换开关，同时决定记录时输入的单位和显示的单位。
- 记录训练时，输入框里的数字按开关当前的单位理解；保存时换算成该力量项自己的单位（现有数据都是 kg）存进 `state.workouts`。**`state.workouts` 的数据格式不变**，已有数据一条都不用改。
- 重新打开一次已保存的训练进行编辑时，输入框按所选单位显示换算后的值，并且来回换算要稳定：用 lb 输入 135，保存后再打开仍然显示 135，不会变成 134.99 或 135.01。
- 如果有手填力量值的入口（`state.lifts` 的手填历史点），输入同样按所选单位理解，保存时换算成该力量项的单位。

### 设置范围（所有者选：跟账号走）
- 所选单位存在账号数据里，手机和电脑自动一致（随现有的同步机制一起同步）。
- 需要在账号的 state 数据里加一个字段，只接受 `"kg"` 和 `"lb"`；`normalize` 要保留这个字段，非法值丢掉。没有这个字段时（旧数据、原 Artifact 的旧备份、旧版本页面保存过的数据）一律按 kg。
- 导出的 JSON 备份带上这个字段，导入时随整份数据一起替换（和其他字段一样）。旧备份的识别（`LEGACY_KEYS`）不受影响，旧备份导入后单位回到 kg。
- 已知的过渡期现象（接受，写进 SUMMARY）：还没换到新版本的设备保存一次 state，旧页面的 `normalize` 会丢掉这个字段，单位设置回到 kg。只影响这个设置，不丢训练数据。

### Claude's Discretion
- 字段名和存放位置（state 顶层的一个小对象或字符串字段都可以），保持现有命名风格（短键名）。
- 换算系数用 1 kg = 2.20462262 lb；显示时最多保留 1 位小数，去掉末尾的 `.0`；存储精度按现有 `woR2`（两位小数）规则，确保来回换算稳定（必要时说明为什么稳定）。
- 只有单位是重量单位的力量项才换算：单位是 `kg`、`公斤`（不分大小写）的按 kg，`lb`、`lbs`、`磅` 的按 lb；单位是「次」等其他文字的力量项、以及趋势图的次数模式完全不变。力量项自己的单位是 lb 时，所选单位为 kg 也要能反向换算。
- 开关的位置和样式：复用健身页现有的 `.seg` 按钮样式和可访问性写法（`aria-pressed`、键盘可用），放在健身页顶部或记录表附近，由 Claude 决定。窄屏（≤560px、375px）布局不能被挤坏。
- 计划编辑器里的目标值和默认起始值仍然按每个力量项自己的单位填写，不改。
- 容量（vol，`kg×次`）指标按所选单位换算重量部分。

</decisions>
